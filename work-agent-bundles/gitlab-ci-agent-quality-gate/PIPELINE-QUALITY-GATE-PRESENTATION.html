01 · Cross-environment route

Expose the evaluation bridge, keep the controller private.

The VirtualService routes only bridge submission and status paths. The bridge calls kagent A2A internally.

Identity and tools

CI gets a short-lived endpoint identity. The bridge and review agents use read-only GitLab access. A GitLab PAT does not authenticate the pipeline to the agent endpoint.

Actual test execution

Test proposals run in disposable, credential-free jobs with bounded resources. Agents cannot declare their own test execution successful or merge code.

The bridge independently resolves the allowed project, open MR and current head SHA, preserves A2A task IDs, and rejects stale evidence. A VirtualService alone provides no authentication.

02 · Merge evidence

Negative testing still produces a passing test.

Test type Expected evidence Gate behavior
Positive Valid input returns the correct result. Candidate test passes.
Negative Invalid input is rejected with the expected error. Candidate test passes by asserting rejection.
Regression The intended assertion fails on the known-bad baseline and passes on the candidate. Both SHA-bound artifacts required.
Peer review Concrete findings with code evidence; no unresolved blockers. Structured PASS plus retained review evidence.

A failed download, missing dependency or crashed baseline executor is not an expected regression failure. Missing evidence, model outage, timeout or a changed MR head blocks the check.

The trusted GitLab gate must be mandatory and tied to the current MR head. Authors must not be able to remove it by editing source CI. Human approval stays separate.
