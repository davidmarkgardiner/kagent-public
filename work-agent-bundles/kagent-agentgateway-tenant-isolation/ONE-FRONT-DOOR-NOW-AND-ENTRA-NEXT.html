What Entra adds3 / 7
Two identity requests · two journeys

Entra supplies the identities and API roles.

Request 1 · inbound

Application → agent

Our AKS application uses its ServiceAccount and caller UAMI to get an A2A API token. Entra assigns the invoke role to that UAMI. The gateway checks the token’s role and exact UAMI identity, then its HTTPRoute reaches one agent.

Request 2 · outbound

Agent → MCP

The agent or its token proxy federates directly to an Agent ID blueprint. A child Agent ID gets an MCP API token with the inherited role. The gateway checks that role and exact child identity and tool, then its route reaches one MCP.

Entra issues signed tokens and grants API roles. It does not pick the Kubernetes Agent Service or MCP Service. Our platform routes and policies still make that decision on every call.
Say it “Entra answers ‘who are you and what API role do you hold?’ The gateway answers ‘may this identity use this route and tool?’”

What stays in place5 / 7
Entra is an added layer

We keep the Kubernetes locks.

✓ Agentgateway

Dedicated listeners, JWT validation, exact HTTPRoutes and MCP tool allowlist. The Entra policy will combine role and exact identity.

✓ Kubernetes

ServiceAccounts, namespace ownership, RBAC, admission checks, ReferenceGrants, restricted Pods and NetworkPolicies.

✓ MCP backend

Its own execution identity and least-privilege access to downstream data or Azure resources.

A valid Entra token alone cannot bypass the gateway’s exact identity/tool checks or Kubernetes network isolation. A new blueprint child may inherit the MCP API role, but still needs explicit gateway onboarding.
Say it “We are upgrading the identity at the front doors. We are keeping the doors, their routes and the walls around them.”

Why this improves the design6 / 7
What changes in practice

Better identity without a wider route.

Today: disposable lab tokens

  • Locally issued JWTs prove the gateway policy and lane isolation.
  • Credential ownership and token refresh are lab-specific.
  • The model path used a shared lab model-gateway key.

With Entra: managed API identities

  • AKS Workload Identity ties token acquisition to an exact ServiceAccount.
  • Entra app roles identify permitted A2A and MCP API use.
  • Gateway checks exact UAMI or child Agent ID, so a shared role does not open every route.
Model Garden is a third, separate identity path. The public repo proposes caller JWT → model gateway → backend UAMI token for Model Garden; it does not yet prove that as the live workplace setup.
