03 · application to agent04 / 10

How another team was stopped

The A2A door checks identity and destination.

Allowed

Right caller, right lane

  • Gateway verifies JWT signature, issuer, audience and expiry.
  • Policy checks lane claims: tenant, purpose: a2a and subject.
  • Platform HTTPRoute forwards to the named agent.
Denied

Wrong caller or side door

  • No token, wrong audience or expired token: 401.
  • Valid signature with rogue tenant/subject: 403.
  • Cross-lane token: 401.
  • Direct controller access: network denied.
A route is not a permission grant. The JWT policy decides who may enter; the platform route decides which Agent Service receives the call.
Say it: “The agent does not ask Entra about each request. The gateway checks the signed token locally against the issuer’s public keys and applies our route policy.”

04 · agent to MCP05 / 10

How another MCP was stopped

The MCP door checks the agent and tool.

Identity

Different token

Runtime token has the MCP audience, purpose: mcp, team and subject. An A2A token fails here.

Route

Exact backend

Platform route points to one named MCP backend. A named ReferenceGrant permits the cross-namespace reference.

Tool

Exact operation

Gateway permits named MCP tools. A forbidden tool is blocked before the MCP server runs.

Agent configuration

RemoteMCPServer.allowedNamespaces: Same and admission stop an Agent from attaching another team’s MCP.

Network and ownership

Default-deny policies block direct MCP Service access. RBAC stops teams editing platform routes, policies and grants. Team administrators can still read Secrets in their own namespace; those tokens are limited to that team’s MCP lane.

Say it: “Even if the agent chooses a tool, it can only reach the MCP gateway. The gateway checks the token and tool, then forwards to one allowed server.”

Keep this credential story precise

Our model route is a separate boundary.

What the isolation lab proves

Agent → existing model gateway

The Agent ModelConfig called the existing lab model gateway using copies of one shared model-gateway API key. That proves the agent could reach the model path.

It does not prove per-team Model Garden JWTs, attribution, quota or a backend UAMI exchange.

Model Garden target

Two distinct identities

A workload sends a gateway-audience JWT to its approved model route. Separately, the gateway backend obtains a Model Garden-audience token through its own UAMI. Model Garden authorizes that backend identity.

Provider endpoint, audience/scope, entitlement and this live token path must be confirmed with the Model Garden owner.

The public repo does not establish that today’s workplace Model Garden connection uses JWT. If that live setup already exists, add its owner-approved claim and runtime receipt before presenting it as a proven current control.
Say it: “The lab model path used a shared key. Our intended Model Garden design uses separate caller and backend tokens; we need its live configuration and denial test to state that as current.”

07 · Entra pilot08 / 10

Real identity test · disposable AKS · 25 September 2026

The Entra pilot worked—and caught a policy bug.

Pilot succeeded

Agent ID tokens over both hops

AKS ServiceAccount federated directly to an Agent ID blueprint, obtained a child token, then passed A2A→Agent→MCP. Wrong audience, forbidden tool and direct Service bypass were denied.

Bug found and corrected

Role and exact identity must be one rule

Separate gateway Allow expressions acted as OR. A rogue identity with the same role initially reached the agent and made one MCP call. A combined role && oid rule denied the retest with 403.

Pilot limits: roles were assigned directly to child Agent IDs; it did not prove blueprint role inheritance. Token rotation used a Secret patch and Pod restart; automatic refresh and expiry failure remain open.
Say it: “The pilot proved the token can move through the full chain. It also proved why a role alone is too broad: the gateway must require the exact onboarded identity and tool.”

08 · future identity work09 / 10

Two requests · two independent grants

Entra issues the rights. Gateway enforces the route.

Request 1 · inbound A2A

Caller UAMI → one agent

AKS ServiceAccount federates to caller UAMI. Entra assigns an A2A API app role to that UAMI. The app gets an A2A-audience token and calls the gateway URL.

Gateway checks issuer + audience + role + exact UAMI oid → named Agent Service

No blueprint required for this caller request.

Request 2 · outbound MCP

Child Agent ID → one MCP route

Agent or token proxy ServiceAccount federates directly to a blueprint. Entra grants the MCP API role to the blueprint principal and configures inheritance. A child gets an MCP-audience token.

Gateway checks issuer + audience + inherited role + exact child oid + tool → MCP Service

Future children inherit the API role, but each still needs gateway onboarding.

An API audience identifies what the token is for. A gateway URL is the HTTP destination. Entra does not select the Agent or MCP Service; platform routes do.
