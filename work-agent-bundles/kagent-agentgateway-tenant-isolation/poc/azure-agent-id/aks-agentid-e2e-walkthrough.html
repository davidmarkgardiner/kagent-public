Identity and traffic, not just manifests

Three credentials. Two guarded doors.

Each pilot ServiceAccount had an exact AKS OIDC federation on a separate blueprint. The caller and runtime Agent IDs had separate API roles and token audiences. A rogue identity had matching roles but the wrong object ID.

The runtime token entered kagent through a temporary Secret header and Pod restart. This is only a lab token lifecycle, not a production broker.

The security finding to carry to work

A role is not an identity.

The first negative test unexpectedly returned 200: two separate Allow expressions behaved as alternatives. The rogue had the role, so it got through even though its Agent ID was wrong.

UNSAFE — OBSERVED
action: Allow
matchExpressions:
  - '"{{ROLE_VALUE}}" in jwt.roles'
  - 'jwt.oid == "{{AGENT_OBJECT_ID}}"'

Same-role rogue reached A2A and caused one backend MCP call in the initial test.

CORRECTED — RETESTED
action: Allow
matchExpressions:
  - '"{{ROLE_VALUE}}" in jwt.roles &&
     jwt.oid == "{{AGENT_OBJECT_ID}}"'

The same-role rogue then received 403 on both A2A and MCP; the approved caller still completed the tool call.

Second architecture correction: AKS Workload Identity → UAMI → blueprint is not a working chain here. The UAMI token was Entra-issued via federation, and the next federation failed with AADSTS700231. Direct AKS ServiceAccount → blueprint federation passed.

Translate the lab into work safely

Manual onboarding first. Automation next.

Infra ID / AACM owners

Approve the blueprint boundary, sponsors, child Agent IDs, separate MCP and A2A API apps, application roles, exact federated subjects, consent, read-back, and revocation. Run the manual process in the private work tenant until an AACM contract is agreed.

AKS and platform owners

Confirm OIDC/Workload Identity, installed CRDs, gateway schema, image/Entra egress, TLS, and a production token broker or refresher. GitOps carries ServiceAccounts, Agent, routes, one-expression policies, grants, and NetworkPolicies.

Joint acceptance

Capture private token-claim read-back and backend counters. Repeat positive A2A→MCP and negative missing audience, role, child ID, forbidden tool, direct bypass, token-expiry and restart cases before promotion.

Scope line: this was a disposable home-lab AKS proof, not AACM execution in the work tenant. The lab used a static Secret header and broad TCP/443 egress; neither is a production-ready credential or egress design.
