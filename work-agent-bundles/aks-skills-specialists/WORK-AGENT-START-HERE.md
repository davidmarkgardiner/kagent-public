# Workplace import and verification

Implement only this bundle; preserve existing object names, Gateway routes, authentication, delivery flow and unrelated work. Agent names are new and intentionally isolated. Do not substitute production credentials or deploy before review.

1. Read README, EVALUATION and the local-validation receipt. Confirm the target kagent CRD supports `spec.skills.gitRefs`, `gitAuthSecretRef`, `initContainer.env`, Python runtime and existing-service-account deployment. Verify native skills-init image, GitLab TLS/CA reachability and the tag clone path on that version. Run server-side dry-run against the explicit lower-environment context.
2. Import the bundle into the existing GitLab skills repository using `scripts/import-to-gitlab.sh CLEAN_CHECKOUT RELATIVE_PATH`, or review an equivalent MR. This copies committed bundle source only, creates an import commit, and does not push. It refuses a dirty target or existing destination. Include the CI template from your root `.gitlab-ci.yml` after configuring an approved internal image with all prerequisites. Do not overwrite an existing root pipeline.
3. Review and push the import branch, run contract/quality/routing gates, merge via existing rules, and create/protect a release tag `aks-skills-<12-character-import-commit-prefix>` at the reviewed import commit. Supply `GITLAB_SKILLS_COMMIT` and matching `GITLAB_SKILLS_REF`. If GitLab import is rebased or merged into a different commit, use that actual commit. The bundle's public GitHub push is not the GitLab skill import.
4. Provision the read-repository-only GitLab Secret out of band in the agent namespace, key `token`. Preserve your existing GitLab authentication convention; do not paste credentials into manifests. Configure a scoped read-only RemoteMCPServer and reviewed tool names through the existing agentgateway. The template has one explicit tool placeholder: expand it only to verified read-only names required by the specialist, with server-side scope and response bounds.
5. Copy `values.example.json` outside Git and fill the target values. `SKILL_CHECK_IMAGE` must be an internally mirrored digest-pinned image containing `python3`. The startup checker uses only the Python standard library. Mirror native kagent images and any reference debug/capture images independently if required; reference capture scripts are not executed by the agents. Python kagent supplies its own file/Bash runtime prerequisites; validate its sandbox in work.
6. Run `python3 scripts/render.py /private/path/values.json /private/path/rendered.yaml`. Read the output. Apply the ServiceAccount, verification ConfigMap and enforced Kyverno policy through Flux **before** adding the Agent CRs. Require a healthy fail-closed Kyverno webhook (`failurePolicy: Fail`) and policy Ready=True. The policy matches these agents' Pod labels and appends the hash verifier after the native init container. Do not disable it to resolve a startup failure. No additional init containers are supported in this first version: the order gate requires exactly the native fetch first and verifier second.
7. Reconcile the Agent CRs in a lower environment. Inspect generated Pod labels, volume mounts and init order. Ensure the GitLab auth Secret is absent from the agent container, /skills is read-only in the runtime, API token is absent, no Azure identity/kubeconfig has been added and MCP denies write/scope-expanding calls. Check a deliberately missing skill/bad credential using an isolated canary; do not disrupt an existing agent.
8. Run `scripts/verify-online.sh CONTEXT AGENT_NAMESPACE CONTROLLER_NAMESPACE /private/path/receipts`. Review actual skills tool-call traces for every mounted skill and body quote. Validate native discovery lists against the lock inventory. Record installed-version evidence; local source inspection is not an installed-version claim.
9. Execute all lower-environment acceptance cases in EVALUATION, record model/token/tool telemetry and independent correctness/safety review. Promote only with the required receipts. Keep existing triage routes unchanged until then. Remove these new CRs/policy/ConfigMap/ServiceAccount through GitOps for rollback; leave shared Gateway/MCP/model resources in place.
