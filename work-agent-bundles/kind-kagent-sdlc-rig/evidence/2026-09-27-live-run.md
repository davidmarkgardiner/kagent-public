## Failures and limits observed

1. The reused GitLab MCP accepted `files` as an untyped array. A malformed
   builder call caused an unhandled exception and empty nested A2A receipt.
   The PoC adapter now declares object items and returns recoverable MCP tool
   errors. A direct builder retry produced the real commit receipt.
2. The first tester call used a rejected branch/path. The narrower prompt and
   recoverable tool errors yielded a successful independent tester retry.
3. The first reviewer probed many irrelevant paths and misread the issue scope.
   The adapter now enumerates four allowed paths and the reviewer reads the
   issues first. The prior review note remains in GitLab as an audit trail.
4. The run required manual retries and a second PM call. It proves the
   individual model, A2A, GitLab, CI, review, and acceptance paths, including
   safe blocked states. It does not prove unattended recovery or durable board
   dispatch. The `agent:plan` trigger is still manual.
5. Kimi uses agentgateway, but GitLab MCP is reached directly. MCP gateway
   policy, a poller with deduplication, a per-project operator workflow, and
   chart-managed gateway placement remain future work.
