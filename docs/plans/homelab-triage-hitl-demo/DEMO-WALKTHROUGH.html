What we are going to demonstrate

A broken rollout.
A reviewed repair.

An agent investigates two signals, proposes one precise change, and waits for a human. We then prove recovery through direct repair and through GitOps.

The Microsoft Teams approval button is the single human gate. The remediation agent then runs the approved commands or merges the code automatically.
Two separate trials. One incident ticket per trial. Both the log and the Event stay attached to that ticket.

    What the human actually approves

    Direct path

    The exact cluster change

    Read the proposed kubectl commands in the Microsoft Teams card. Click Approve remediation; the agent receives authority and executes them without another human confirmation.

    • Only the unmanaged checkout-api fixture.
    • Only its approved APP_MODE value.
    • Approval bound to proposal digest, workflow and expiry.
    • The write MCP rechecks permission at the point of effect.

    GitOps path

    The reviewed repository change

    Read the proposed diff and MR head in Microsoft Teams. Click Approve and merge PR; the remediation agent merges automatically. No further human PR review or manual merge.

    • One manifest path and one validated configuration diff.
    • CI verifies the allowed change; CI does not deploy.
    • Flux is the cluster writer for this fixture.
    • The scoped agent merge identity has protected-target merge permission.

    How we know it worked

    The old healthy replica makes these checks essential: a health response alone can hide a failed rollout.

    EvidenceRequired observation
    Human decisionVerified Teams approver identity and exact command or MR-head approval; agent command/merge receipts follow that single decision.
    EffectThe agent runs approved kubectl through write MCP or merges the approved MR; record actual argv/results or merge/squash target commit.
    GitOps deliveryFlux applied the reviewed commit or a proven descendant with the approved manifest unchanged.
    RolloutDesired and observed generations agree. Desired replicas are updated and available; the failed obsolete ReplicaSet has scaled down.
    ApplicationCorrect desired configuration and 120 seconds of stable health/restart observations. Old Events may remain in history.
    Incident historyThe original ticket records evidence, reasoning, decision, action and proof. Missing proof remains visible as failed, blocked or unknown.
