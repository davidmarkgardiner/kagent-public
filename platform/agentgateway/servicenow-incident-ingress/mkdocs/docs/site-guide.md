# MkDocs version of the incident intake handoff

This is a buildable MkDocs 1.6.1 project with navigation, search, code examples,
downloadable YAML/JSON/scripts and the reusable work-agent skill. It includes the
AKS Istio path, Entra role enforcement guidance, recorded lab proof and explicit
limits of that evidence. Nothing here deploys a website or changes a cluster.

The checked-in `docs/` directory is generated from the authoritative READMEs,
examples and sanitized receipts in the parent handoff folder. A copy of this
MkDocs folder can build independently; copy the entire parent handoff folder if
you also want to refresh it from the canonical sources.

## Build and preview

Run from this folder:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m mkdocs build --strict
.venv/bin/python -m mkdocs serve --dev-addr 127.0.0.1:8000
```

Open http://127.0.0.1:8000/ while the preview server runs. The built static site
is `site/index.html`; `use_directory_urls: false` also makes the nested page
links work when opening the generated files locally. Dependencies must be
available from an approved package source in a restricted environment. The
built-in theme needs no custom theme, CDN, Mermaid renderer or third-party
MkDocs plugin. Flow diagrams use plain text so they remain readable offline.
Code blocks are plain preformatted text; CDN-based syntax highlighting is disabled.

## Refresh the MkDocs copy

Edit the canonical READMEs or examples in the parent folder, then run:

```bash
python3 prepare_docs.py
python3 prepare_docs.py --check
.venv/bin/python -m mkdocs build --strict
```

The preparation script copies only its explicit public-file list, rewrites local
links and prepares a download index. It never copies local values, authentication
headers, rendered workplace manifests, private receipts, virtual environments or
existing site output. It refuses unknown files in the generated docs directory
instead of deleting them. Commit both the canonical change and refreshed docs.
If a canonical Mermaid diagram changes, update its reviewed text equivalent in
`prepare_docs.py`; the generator stops rather than silently retaining an old flow.

The synchronization check needs the complete parent folder and the three linked
gateway references plus the shared A2A helper from the source repository. It is
not needed to build the checked-in MkDocs project after copying this folder.

## Install the work-agent skill

The complete portable skill is in
[skills/mkdocs-work-agent](skill.md) in the parent
handoff folder. Copy that whole folder to the work agent's configured skill
directory. For Codex, use `${CODEX_HOME:-$HOME/.codex}/skills/mkdocs-work-agent`.
Inspect an existing installation before replacing it.

For an agent without skill discovery, tell it to read `SKILL.md` as its task
instructions and retain the linked assets. Example invocation:

```text
Use $mkdocs-work-agent to document this project in MkDocs format. Reuse the
existing project sources and configuration, preserve evidence boundaries, add
working navigation and file links, and verify a strict build. Do not deploy it.
```

The skill includes a minimal starter project for future documentation tasks.
In this handoff, use the existing synchronization script rather than generating
a competing copy. Authentication-policy YAML is still not generated by the AKS
starter; converting the docs to MkDocs does not change that implementation scope.

Official format guidance: [MkDocs](https://www.mkdocs.org/),
[configuration](https://www.mkdocs.org/user-guide/configuration/) and
[writing documentation](https://www.mkdocs.org/user-guide/writing-your-docs/).
